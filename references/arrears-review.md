# 欠费跟进样例工具

仅在使用者确认账单、收款、对应关系、记录完整性和所用口径时考虑使用。脚本是按明确账单编号关联的试验工具，不适用于凭商户名推断、多账单合并付款、部分抵扣、跨期分摊或自动认定预收；这些情况保留为待核对，不能代使用者编造分配规则。

标准化测试工作簿需有“账单”及“收款”两个工作表。第一行字段：
- 账单：账单编号、商户编号、商户名称、费用期间、费用类型、应收金额、账单已确认、收款记录完整。
- 收款：收款编号、账单编号、收款金额、收款已确认。

编号为文本，费用期间与费用类型为明确文本；金额为非负、最多两位小数，确认和完整字段只有明确“是”才视为满足。完整是针对该账单覆盖范围的业务确认，不能由缺少收款行推断。若资料不是这种结构，不能擅自修改原表或猜测映射；先确认含义，在独立临时文件中标准化并保留源文件、来源行和映射依据。涉及一对多或无明确编号的付款不得臆测。

使用 python scripts/arrears_review.py INPUT.xlsx --out OUTPUT.xlsx。输出含跟进清单、异常记录与汇总，拒绝覆盖。待核对项不纳入已确认余额，无可确认记录时余额留空；存在未能唯一关联的收款时，全部账单暂列待核对直到核清影响范围。有关同名商户、重复编号、超额收款、未知金额及不完整记录不可自动合并。

工具生成的余额为材料及输入规则下的候选汇总，需按业务流程和财务记录核对，不自动催收、发函或改变原台账。根据已确认结果和现行模板准备草稿，缺少付款期限、收款方式、联系人和日期等则标待确认。当前仅经有限虚构数据本机测试，业务口径、实际样表、格式和目标平台仍需验收。

若表中出现未识别的有名字段（如调减、税费、抵扣）或无表头但有数据的列，工具停止，不计算余额；需先确认口径并完整保留源资料后再处理。不能为了通过工具而丢弃影响金额的列。
如果工作簿中另有包含内容的未识别工作表，工具停止输出，须核实是否包含与本任务相关的信息；空白附加表不影响运行。不能删掉影响业务的工作表以强行通过。
如用户需要空白测试格式，可运行 python scripts/make_blank_forms.py --kind arrears --out 空白模板.xlsx。模板没有业务数据或默认确认状态；已有公司台账优先按其实际字段理解，不能为适配测试工具而丢弃信息。

空白模板只对前 200 行的编号及指定文本列预设文本格式；超过后应检查单元格格式，特别是编号前导零。打印效果需在使用软件中预览。\n
当用户要求从标准账单准备催缴函草稿，且模板正文中分别有唯一单文字节点占位符“【商户名称】、【费用期间】、【费用类型】、【金额】”时，可用 python scripts/arrears_notice.py --ledger INPUT.xlsx --bill-id 编号 --template TEMPLATE.docx --out DRAFT.docx。该工具先重新执行台账核对，只允许指定的需跟进账单，另存并校验指定替换；未知付款期限、收款方式等维持模板原样。模板不可用、字段不匹配或账单待核对/已结清时停止，不自动发送。完成后应由相关人员核对财务口径并逐页查看页面；不支持自动保证所有模板版式。临时核对文件存放于输出目录下的临时文件夹，运行结束会清理。

工具会检查工作簿批注：仅允许未修改的内置空白模板表头提示，数据批注、其他表头批注及讨论批注须先人工核实，工具会停止输出。不能删除有业务意义的备注以绕过检查。\n
标准化工作表中存在公式时，脚本不会计算或使用公式文本作为业务值，会停止输出并指明单元格；应先用可用的表格工具核实计算结果及口径，再依据经核对的数据制作独立输入，保留原始文件和来源。
