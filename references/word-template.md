# Word 模板填充与验收

使用原 DOCX 作为模板，确认用户明确要填写的具体位置及内容，保留原文件并生成新文件。先检查正文、表格、页眉、页脚以及是否涉及文本框、域、修订、内容控件、嵌入对象或其他特殊结构。用户未提供模板时可先生成草稿，不将新建文件称作保留了原模板。

## 定点填充

工具来源：本地合同助手 v2.1 的 find_docx_occurrences.py、fill_docx.py、compare_docx.py，位于本技能 scripts/；另有本技能 verify_docx_expected.py。均为 Python 标准库脚本。查找工具输出可能含文档片段，按实际平台权限处理，不要将正式合同或个人信息写入技能文件。

1. 明确用户指定的原文与替换值。用 python scripts/find_docx_occurrences.py TEMPLATE.docx --text "原文" 定位正文及表格段落的每个目标并记录来源 SHA-256。它不覆盖页眉、页脚及全部特殊对象，须另行核查。
2. 仅当目标位于正文或正文表格、每个目标在单个文字节点内且唯一、无交叉重叠并符合用户要求时，用 python scripts/fill_docx.py TEMPLATE.docx --out OUTPUT.docx --expect-sha256 源文件哈希 --replace "原文=>新值" 另存；多项使用多个 --replace。原文含 => 的情形不适用该命令。无用户明确要求不要使用 --all。工具只修改 word/document.xml，不修改页眉页脚；不适用就停下并说明，不能擅自改模板或保证安全。
3. 生成临时 JSON 替换计划（由 old 和 new 键组成的对象列表），用 python scripts/verify_docx_expected.py TEMPLATE.docx OUTPUT.docx --plan PLAN.json 校验实际正文文本是否与唯一替换计划一致、其余包成员是否完全相同及正文其他 XML 结构和属性是否不变。该工具不支持对重复目标使用 --all；可用 compare_docx.py 补充列出段落改动并人工核对。计划可能包含敏感信息，保存在适当的临时工作目录，不写进通用技能或对外分享。
4. 再用目标 Word/WPS 环境将原文和新文渲染成页面，逐页检查字体、表格、图片、页眉页脚、分页、换行和溢出；替换内容较长尤其需要核对。必要时结合用户提供的格式要求确认可接受的版面变化。清楚报告“结构检查”和“页面视觉检查”各自结果；没有页面渲染条件时只能说明结构检查结果与视觉未验证，不能承诺格式或页面完全一致。检测出不符先修正并复验，无法修复则说明。

跨文字片段的占位符、重复目标、页眉页脚、文本框、域、修订、受保护或带宏文档等复杂情况可能不能由该工具安全处理。拒绝意味着未生成结果，不代表这些格式绝对无法处理；需要具备相应能力的工具和单独验证。即使 XML 结构相同，文字长短变化、字体环境和渲染软件也会影响分页与视觉布局。不同模板均须实际验证，不能宣称所有模板均已证明。
