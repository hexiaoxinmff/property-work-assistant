# 保洁整改事件跟进工具

适用于经使用者确认事件含义、每条记录可唯一归属某个事项的结构化记录；没有编号、时间或不确定是否为同一问题时，先由使用者确认，不能根据相似位置或照片自行合并。可先按现有资料整理文字清单，不强制先准备标准表。

测试格式的 XLSX 有名为“巡检记录”的工作表，第一行依次包含：记录编号、事项编号、记录时间、事件、位置、问题、负责人、期限、说明。编号为文本；记录时间为 Excel 时间或明确的 ISO 时间。试验事件类型为“发现、已通知、反馈已完成、复查通过、复查不通过”；这些仅用于测试映射，实际组织的业务含义须由使用者确认。

运行 python scripts/cleaning_followup.py INPUT.xlsx --out OUTPUT.xlsx，输出“整改跟进”和“异常记录”。跟进表按记录状态给出建议下一步，仅供人工确认，不能理解为已经安排、已通知或完成。按同一事项的记录时间整理最新事件；“已通知”仅记为已通知待反馈，不推断整改已经开始；保洁反馈完成仅为待复查，只有输入中明确有复查通过才显示已复查通过。缺负责人/期限写待确认；缺发现记录、重复记录编号、同一事项时间冲突或无法归属的记录会使有关结果待核对。资料不完整时不推断现场情况、责任或实际完成进度。

仅基于有限虚构样例本机测试；该工具不识别照片、不操作内部系统、不自动发送消息；各组织的巡检制度、实际模板与目标平台需要另行验证。

如果出现未识别的有名字段或无表头但有数据的列，工具会停止输出，须先核实这些信息的含义；不能为通过工具而直接丢弃可能影响复查结论的字段。工具不会理解自由文字里的矛盾，事件与说明的业务含义仍需人工核对。
如果工作簿中另有包含内容的未识别工作表，工具停止输出，须核实是否包含与本任务相关的信息；空白附加表不影响运行。不能删掉影响业务的工作表以强行通过。
同一事项在同一天有多条记录，且至少一条只精确到日期时，先后无法确定，标记待核对。Excel 读出的零点日期时间难以区分日期与真正零点，因此保守按日期处理；确系零点时可提供明确的 ISO 日期时间文本并经使用者核对。不同日期仍按日期顺序处理。
如用户需要空白测试格式，可运行 python scripts/make_blank_forms.py --kind cleaning --out 空白模板.xlsx。模板没有业务数据或默认确认状态；已有公司台账优先按其实际字段理解，不能为适配测试工具而丢弃信息。

空白模板只对前 200 行的编号及指定文本列预设文本格式；超过后应检查单元格格式，特别是编号前导零。打印效果需在使用软件中预览。\n
工具会检查工作簿批注：仅允许未修改的内置空白模板表头提示，数据批注、其他表头批注及讨论批注须先人工核实，工具会停止输出。不能删除有业务意义的备注以绕过检查。\n
最新事件说明仅取该事件自身的说明，缺失时标“未提供”，不沿用旧事件的说明；存在顺序或记录问题时最新事件标待确认。负责人和期限为最近记录值，不代表仍是当前负责人或现行期限，输出对应来源行并提示人工确认；记录有疑问时不猜测。\n
标准化工作表中存在公式时，脚本不会计算或使用公式文本作为业务值，会停止输出并指明单元格；应先用可用的表格工具核实计算结果及口径，再依据经核对的数据制作独立输入，保留原始文件和来源。

同一事项不同记录出现不同位置时标待核对，先核实是否同一事项或位置调整；不直接视为复查通过。
